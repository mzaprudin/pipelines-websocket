# Методика измерений

[English](benchmark-methodology.md) · [Русский](benchmark-methodology.ru.md)

Контрольная ревизия и новые сборки измеряются последовательно на одной машине: Release/x64, 5 warmup и 15 measurement итераций с целевым временем 500 мс, один launch. Ошибка в таблице — полуширина 99,9% доверительного интервала BenchmarkDotNet. Выбросы обрабатывает BenchmarkDotNet; полные значения, интервалы, GC и аллокации сохранены в JSON. Длительность итерации — целевая, а не жёсткая.

Четыре echo-случая: 128/4096 байт × Pipelines/ClientWebSocket, побайтная проверка полного обмена. Шесть streaming-запусков: два клиента по три свежих процесса, 10 соединений, JSON 87 байт, 20 фреймов на запись, 5 секунд прогрева и 30 секунд измерения. Порядок клиентов чередуется между повторениями.

Сервер передаёт подготовленные batch по 1780 байт. Прогрев исключён из счётчиков; скорость — сообщения / фактическое время по монотонным часам. Проверяются профиль, завершение без ошибок, сумма samples и Bytes = Messages × 87. CPU/GC/аллокации loopback относятся ко всему процессу, включая сервер и метрики; сетевые архивы измеряют только приёмник. kB = 1000 байт; память на миллион считается из неокруглённого AllocatedBytes / Messages.

Исходные Ethernet-матрицы сохранены целиком. Автоматический TCP-буфер — отдельный контроль с одним удалённым присваиванием; текущая библиотека задаёт фиксированный 64 KiB. Новых физических сетевых измерений при разделении не выполнялось.

```sh
python3 scripts/run-benchmarks.py --output results/local/MY_RUN
python3 scripts/render-results.py results/local/MY_RUN
```

Для сравнения до/после скопируйте соответствующие контрольные отчёты в MY_RUN/baseline/. Скрипт сохраняет команды, окружение, SHA-256 исходников и бинарников, полный BDN stdout и JSON/CSV/Markdown. render-results проверяет данные, создаёт summary.json и обе README-таблицы. verify-evidence проверяет перенесённые файлы и опубликованный набор.

Изменение времени после переноса само по себе не доказывает изменение алгоритма: JIT, размещение кода, планировщик и фоновые процессы влияют на результат. Сравнивайте интервалы и исходные значения. Цель проверки — корректность и сохранение zero-allocation сценариев; задержки хвоста отдельно не измерялись.
