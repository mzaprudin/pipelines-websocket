# pipelines-websocket

[English](README.md) · [Русский](README.ru.md) · [CI](https://github.com/mzaprudin/pipelines-websocket/actions/workflows/ci.yml)

WebSocket-клиент на TCP/TLS для непрерывного потока небольших сообщений — например, сделок и котировок — на C# / .NET 10. System.IO.Pipelines хранит принятые байты в памяти из пула и передаёт содержимое сообщений прямо обработчику приложения.

В приёме используется **zero-allocation подход**: прогретый путь нефрагментированного сообщения обходится без отдельного массива под данные. Обработчик заимствует байты до завершения обработчика. Подключение, рост пула и сборка фрагментов имеют отдельные затраты памяти.

## Инженерные решения

- **Явное время жизни памяти.** Нефрагментированное сообщение передаётся как заимствованный `ReadOnlySequence<byte>`; Pipe освобождает память после завершения обработчика. Данные для дальнейшего хранения копирует приложение.
- **Ограниченная обработка входа.** Фрагменты собираются отдельно с лимитом 1 MiB. Пороги backpressure Pipe позволяют принять полный фрейм без блокировки записи в Pipe.
- **Управляемое завершение соединения.** Циклы чтения и заполнения Pipe поддерживают отмену; отправки сериализованы. Один владелец управляет жизненным циклом и наблюдает обе задачи при завершении.
- **Проверка протокола.** Проверяются HTTP upgrade, границы фреймов и control-трафик; TLS использует обычную проверку сертификата. Стандартный ClientWebSocket служит вариантом сравнения в измерениях.

## Сборка и запуск примера

Требуется .NET 10 SDK:

```sh
dotnet restore Pipelines.WebSockets.sln --locked-mode
dotnet build Pipelines.WebSockets.sln -c Release --no-restore
dotnet test tests/Pipelines.WebSockets.Tests -c Release --no-build
dotnet run -c Release --no-build --project samples/Pipelines.WebSockets.Demo
```

[Пример](samples/Pipelines.WebSockets.Demo/Program.cs) передаёт 100 пронумерованных сообщений через Pipelines и адаптер ClientWebSocket, проверяя каждый байт и порядок сообщений. Тесты используют настоящие локальные TCP/TLS-соединения: размеры фреймов, фрагментацию, некорректный upgrade, отмену и доверие сертификату. CI на Linux и Windows также проверяет benchmark-сценарии и streaming; Windows собирает и запускает переносимый генератор.
